# YouTube performance review

Read when the creator asks what is working, requests a review of recent video/channel results, or wants performance evidence considered in strategy. Use current official YouTube guidance for metric definitions and a current Studio layout; Analytics views can change.

## Inputs and scope

- Use creator-provided Studio exports, screenshots, or reports, or data that is already available in the authorized workspace. Never ask for account credentials or claim access to private Studio data you cannot see.
- Identify the date range, timezone if relevant, channel/video scope, format, traffic surfaces, and available metrics. Check whether a report covers the same period for each item. If a missing field would materially change the conclusion, ask only for that export or screenshot; otherwise continue and state the limit.
- Use one or more specific questions such as: Which topics brought search viewers? Which recent long-form videos earned broader reach? Where did viewers leave? Did a title/thumbnail test produce a clear result?
- For channel-level context, compare like with like: format, video age or lifecycle window, duration when relevant, traffic surface, and reporting period. Use the creator's own typical performance as context where available. Do not apply generic “good CTR” or retention thresholds across channels.

## Read the evidence in context

Organize findings around the question, using relevant measures only:

- **Reach and appeal:** impressions, traffic sources, and impressions click-through rate. Separate Search from Browse/Home, Suggested, and other sources; they represent different viewer intent. Read CTR together with impression volume and audience mix. A lower CTR as reach expands can still accompany broader growth.
- **Viewing behavior:** watch time, average view duration, retention or key moments where available, and the opening promise. Compare videos with compatible format, length, and audience context. Do not diagnose a retention problem from a single aggregate number when the curve or comparable examples are missing.
- **Audience and topic evidence:** search terms, new/returning or casual/regular audience reports, what viewers watch, and Trends insights when available. Treat limited or missing reports as unknown, not zero.
- **Packaging experiments:** use native YouTube title/thumbnail test results when supplied. Record whether the test reports a winner, similar performance, or inconclusive outcome. Do not treat CTR alone as the goal or a small observational change as a causal experiment.

For each conclusion, show the comparison and evidence behind it. Label:

- **Observed:** directly present in the supplied report.
- **Interpretation:** a plausible explanation consistent with the data.
- **Unknown:** not supported by the available reports.

Do not claim that one factor caused a result unless the data supports a controlled comparison. Views, subscribers, or CTR in isolation do not explain performance. Separate topic demand, packaging response, viewing behavior, and audience-fit explanations where the reports allow it.

## Deliver the review

Unless the creator asks for a different output, provide:

1. **Scope and data quality:** date range, formats/surfaces covered, missing fields, and important comparison limits.
2. **What stands out:** a short ranked set of findings with actual values and matched comparisons where useful.
3. **What it may mean:** interpretations and confidence, clearly separated from observations.
4. **Next actions:** up to three ideas to repeat, adjust, or test. Tie each action to evidence and a future signal to inspect; do not promise a view lift.
5. **Topic Scout handoff:** summarize only reusable topic/audience learnings. Topic Scout can use this dated report when ranking future opportunities; it must respect its scope and confidence rather than treat one video as a channel-wide rule.

## Saving and channel memory

Return the analysis in chat unless the creator asks to save it. If asked and no existing analytics convention applies, save a concise dated report as `analytics/YYYY-MM-DD-performance-review.md` in the channel workspace. Keep source report names, date range, and metric definitions; do not duplicate complete exports, unnecessary account details, or sensitive raw data into the report.

Do not automatically change `CHANNEL_MEMORY.md` based on one performance result. If the creator confirms a durable strategy or preference, update the relevant memory guidance as creator-confirmed and date the change. Keep video-specific findings in this report or the video's project.
